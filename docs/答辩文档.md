# Locifab 本地文件工坊 · 答辩文档

> 版本：11.0.3（正式版）
> 平台：Windows 10 / 11，x64
> 形态：完全离线、自包含单文件、U 盘即插即用
> 技术栈：C# / .NET 8 / WPF（手写 MVVM，无第三方 NuGet 依赖）

---

## 1. 项目一句话介绍

Locifab 是一个面向普通用户与小型团队的**离线文件处理工作台**：把重命名、格式转换、图片压缩、去重、清理、备份、校验、分类、拆分合并、流水线等高频操作集中到一个本地软件里，并统一提供“先预览、再执行、可回退”的安全流程。

不联网、不安装运行环境、不上传文件；所有操作在本机完成。

---

## 2. 为什么做这个项目

### 2.1 真实痛点

- 文件处理工具分散：重命名、压缩、转换、去重、校验分别装不同软件。
- 在线工具需要上传文件，隐私和网络不可控。
- 批量操作不可逆：改错名字、移错目录后很难恢复。
- 命令行工具对普通用户门槛高。
- 免费工具常带广告、捆绑安装、强制联网。

### 2.2 设计目标

1. **完全离线**：文件不出本机。
2. **零安装**：单文件 exe，复制到 U 盘即可运行。
3. **先预览再执行**：所有批量操作先生成计划。
4. **可回退**：基于本地日志逆向恢复，不依赖系统撤销。
5. **新手可用**：中文界面、步骤引导、功能说明。
6. **可扩展**：流水线与配置模块化，便于复用。

## 3. 总体架构

```text
LocalCraft.App         WPF 界面层：窗口、页面、ViewModel、交互
LocalCraft.Core        核心层：文件扫描、重命名、日志、回退、备份、校验、分类等
LocalCraft.Conversion  转换层：图片 WIC、OOXML/文本/HTML、PDF 输出
tests/SelfTest         核心自测：182 项断言
tests/Harness          流水线端到端测试：模板真实执行
```

### 3.1 分层职责

| 层 | 职责 |
|---|---|
| App | 导航、页面、拖拽、动画、设置、配置记录 |
| Core | 文件操作、日志、回退、扫描、校验、模板、拆分合并 |
| Conversion | 图片/文档转换引擎与格式适配 |
| Tests | 核心断言与流水线真实文件测试 |

### 3.2 关键技术选择

- **WPF + 手写 MVVM**：不引入框架依赖，发布体积可控。
- **System.Text.Json**：日志、模板、配置本地持久化。
- **WIC**：Windows 原生图片编解码，免安装 ImageMagick。
- **单文件发布**：`PublishSingleFile` + 自包含运行时。
- **自定义 ZIP 加密**：兼容标准 ZipCrypto，支持密码压缩/解压。

## 4. 功能地图

### 4.1 文件整理

- 批量重命名：前缀、后缀、查找替换、序号、排序方式。
- 扫描与分类：按类型/年份/月份/名称前缀规划移动。
- 备份同步：只增不删、严格比对、SHA-256。
- 实时监控：只记录变化，不自动处理。
- 压缩与解压：ZIP 压缩、解压密码、路径穿越防护。
- 空目录清理：空目录与 0 字节文件。
- 时间与属性：修改时间、只读、隐藏、存档。
- 校验与清单：SHA-256 清单生成/校验。
- 文件夹清单：目录树 + CSV/HTML 导出。
- 拆分与合并：大文件分片、分片合并。

### 4.2 文本与内容

- 文本替换：正则、扩展名范围、备份与回退。
- 元数据清理：DOCX/XLSX/PPTX 属性、图片 EXIF。
- 内容去重：中文二元组 + SimHash 相似分组。
- 相似照片：感知哈希 + 阈值分组。

### 4.3 图片与媒体

- 图片批处理：缩放、格式、质量、水印。
- 图片压缩：目标 KB，自动质量与尺寸下降。
- 图片检查：损坏/截断检测与隔离。
- 内嵌图片：Office 媒体提取、PDF 内嵌 JPEG。

### 4.4 效率与自动化

- 任务流水线：步骤编排、预览、执行、日志、模板。
- 功能配置：保存/应用/导出/导入当前工具设置。
- 流水线导入：按“功能 → 模板”导入为步骤。
- 回退中心：逐条记录、删除、逆向恢复。

## 5. 安全与可回退设计（核心亮点）

### 5.1 先预览、再执行

- 重命名：显示旧名 → 新名、冲突、覆盖。
- 分类：显示旧路径 → 目标路径。
- 转换/压缩/提取：显示输出路径与数量。
- 流水线：显示步骤顺序；执行在工作副本上进行。

### 5.2 操作日志

每次批量操作先写日志，再改文件：

```text
journal
 ├─ kind / displayName
 ├─ sourceDirectory
 ├─ operations[]
 │   ├─ sourcePath
 │   ├─ targetPath
 │   ├─ backupPath
 │   └─ state
 └─ status / completedAt / undoneAt
```

日志保存在本机，回退中心按批次恢复。

### 5.3 回退能力

- 移动/重命名：目标路径移回原路径。
- 转换/压缩/提取/清单：删除本次输出。
- 标签/配置：恢复旧文件或删除新增文件。
- 失败补偿：中途失败自动回滚已处理项。

### 5.4 数据目录回退

当 `%LOCALAPPDATA%\Locifab` 不可写时，自动回退到：

1. 程序目录 `LocifabData`
2. 临时目录 `%TEMP%\Locifab`

避免“日志写不进去导致整个功能不可用”。

## 6. 流水线设计

### 6.1 执行模型

1. 选择源目录与输出目录。
2. 添加步骤、调整顺序与参数。
3. 只读预览。
4. 执行：
   - 创建源目录工作副本；
   - 按顺序执行；
   - 每步写入日志；
   - 输出写入输出目录。

### 6.2 模板

内置模板包括：

- 交付打包
- 隐私交付
- 审计清单
- 照片交付包
- 备份前审计
- 文档隐私交付
- 课程资料归档
- Office 素材提取
- 项目目录初始化
- 上架图片包
- 标签化归档等（以当前版本为准）

### 6.3 配置模块

- 每个功能保存多套命名配置。
- 保存时生成流水线步骤快照。
- 流水线按“功能 → 模板”导入。
- 导入步骤只显示“模板：名称”，参数隐藏。
- 执行使用保存时快照，避免参数丢失。

## 9. 演示流程（答辩现场建议 5–8 分钟）

### 第 1 步：首页与侧栏

- 展示分类配色、折叠侧栏、开始使用。
- 说明完全离线、单文件运行。

### 第 2 步：批量重命名

- 选择 `01-重命名`。
- 设置前缀/后缀/序号/排序。
- 预览旧名 → 新名。
- 执行后打开回退中心，演示恢复。

### 第 3 步：图片压缩 / 检查

- 选择 `02-图片压缩`，设置目标 KB。
- 选择 `03-图片检查`，展示损坏图片隔离。

### 第 4 步：流水线

- 打开 `00-流水线输入`。
- 选择“全流程-输入整理交付”。
- 预览步骤，执行。
- 展示输出目录与日志。

### 第 5 步：配置模块

- 在某个功能保存配置。
- 流水线右侧选择“功能 → 模板”。
- 添加为步骤，展示“模板：名称”。

### 第 6 步：回退中心

- 查看记录列表。
- 选择批次回退。
- 展示逐条删除记录。

## 10. 创新点与亮点

1. **离线优先**：不依赖网络、不依赖外部引擎。
2. **统一安全模型**：预览、日志、回退贯穿所有批量操作。
3. **可组合流水线**：步骤、模板、配置模块化。
4. **配置快照**：解决“工具配置导入流水线后参数丢失”。
5. **可移植**：自包含单文件，U 盘即插即用。
6. **异常鲁棒性**：坏文件跳过、同名自动编号、日志目录回退。

## 11. 已知限制

- 视频裁剪未实现：当前没有内置视频编码器，避免生成损坏文件。
- PDF 内嵌图片只提取可识别的 JPEG 图像流；矢量 PDF 不支持。
- HEIC/RAW 依赖 Windows 系统解码器。
- 内置 PDF 排版引擎以视觉还原为主，复杂表格/公式有限。
- 大规模目录扫描受磁盘与权限影响。
- 部分工具 UI 尚未逐页自动化点击测试，核心服务由自测覆盖。

## 13. 常见答辩问题

### Q1：为什么不用 Python/Electron？

A：目标是无运行环境、单文件、Windows 原生文件操作。.NET 8 + WPF 自包含发布更符合“U 盘即插即用”。

### Q2：如何保证误操作可恢复？

A：所有批量操作先写日志；文件移动/重命名记录旧路径与新路径；输出类操作记录输出路径；回退中心逆向执行。

### Q3：如何处理重名？

A：预览阶段标出冲突；流水线分类/重命名自动追加 `_2`、`_3`，不覆盖已有文件。

### Q4：流水线为什么在工作副本上执行？

A：避免直接改动源目录；失败时可以清理工作副本，源文件保持原样。

### Q5：日志写不进去怎么办？

A：数据目录自动探测，失败时回退到程序目录或临时目录。

### Q6：为什么视频裁剪没做？

A：没有内置视频编码器时直接拼接会产生损坏文件；宁可暂不交付，也不做假功能。

## 15. 结语

Locifab 的核心不是“功能堆叠”，而是把**离线、安全、可回退**做成统一的产品约束：每一个批量操作都能预览，每一次修改都有日志，每一次失败都尽量可恢复。这也是本项目与其他文件工具最大的区别。
